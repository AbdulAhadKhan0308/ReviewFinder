# Acceptance

The acceptance criteria for the restaurant review platform, and the results of checking each one. The requirements
behind them are in [requirements.txt](requirements.txt).

Each item was checked in the web app on 17 Oct 2026, using it as a reviewer or owner would. For every item this page
lists what was expected, what was observed, and screenshots from [screenshots/](screenshots/).

**Result: 22 items pass; 4 are partly covered.** Items 14, 15, 16 and 21 are about requests sent directly to the API,
bypassing the app. The app's side of each passes; the direct-request part can't be shown from the app and isn't
included here.

## Acceptance criteria

Confirmed-scope checks

1. [x] A user can register as either supported role and sign in.
2. [x] Invalid registration/sign-in input produces clear errors.
3. [x] A reviewer sees restaurant summaries and can open restaurant details.
4. [x] Cuisine and average-rating filters work individually and together.
5. [x] Keyword search finds restaurants by title, location or description.
6. [x] Selecting several cuisines shows only restaurants that have all of them.
7. [x] Rating filter supports a minimum threshold and a min-max range.
8. [x] With a rating filter on, restaurants with no reviews are hidden.
9. [x] Highest-rated-first is the initial default; either direction can be selected.
10. [x] Selected filters and sort direction survive leaving and returning.
11. [x] An owner can create, view, update, and delete their own restaurants.
12. [x] Image upload accepts only JPG/JPEG, PNG or WebP files up to 5 MB.
13. [x] Restaurants without an uploaded image show the default image.
14. [x] Another owner cannot update/delete those restaurants via direct API calls.
15. [x] Owners cannot view other owners' restaurants or write reviews, even via direct API calls.
16. [x] Unauthenticated users cannot view or change restaurants or reviews, even via direct API calls.
17. [x] Empty lists, failed requests, and missing restaurants are handled gracefully.
18. [x] Web navigation meets the SPA/hydration requirement.

Review checks

19. [x] Only reviewers can create reviews; ratings are integers 1 to 5, text optional.
20. [x] A reviewer can post more than one review for the same restaurant.
21. [x] New reviews and restaurants take their author/owner from the session, not the request.
22. [x] Review changes update the displayed average, count, filtering, and sorting.
23. [x] Users cannot edit/delete another reviewer's review.
24. [x] Reviews can be filtered by keyword, rating range and date range, and sorted by rating or date in either
    direction; reviewers and owners both can do this.
25. [x] A restaurant's average rating and review count cover all its reviews, whatever review filters are applied.
26. [x] Review filters start cleared on each restaurant; restaurant list filters and sort are remembered.

## How it was tested

- **App:** the current `main` branch (commit `7c09854`), API and client run locally against the Docker PostgreSQL database.
- **Browser checks:** Microsoft Edge (headless) driven by Playwright at 1280 × 900, clicking and typing as a user would.
  Every screenshot was taken during these runs.
- **Failed requests:** simulated by blocking or failing specific API calls in the browser (item 17), plus one run with the
  API actually stopped.

## Reviewers' restaurant list

### 3. A reviewer sees restaurant summaries and can open restaurant details — ✅ Pass

**Expected:** a list of all restaurants, each showing image, name, location, cuisines and average rating (or "No
reviews"); selecting one opens its own page.

**Observed:** Rita sees all 9 restaurants from both owners, each card with image, name, location, cuisine chips and
"★ 4.67 · 3 reviews" or "No reviews" (10). Clicking Trattoria Bella opened `/restaurants/{id}` showing the full image,
location, cuisine, "★ 4.20 · 5 reviews", description, date added and its reviews (11).

### 4. Cuisine and average-rating filters work individually and together — ✅ Pass

**Expected:** each filter narrows the list on its own, and combining them shows only restaurants matching both.

**Observed:**
- **Italian only:** Trattoria Bella, Fusion Kitchen, La Pino's Italia, Pizza Uno (14).
- **Min rating 3.5 only:** Sakura Sushi, Trattoria Bella, Taco Fiesta (16).

  correctly excluded.

### 7. Rating filter supports a minimum threshold and a min-max range — ✅ Pass

**Expected:** a minimum alone, a maximum alone, or both as an inclusive range; decimals up to 2 places.

**Observed:**
- **Min 3.5:** Sakura Sushi (4.67), Trattoria Bella (4.20), Taco Fiesta (3.50, included because the limit is inclusive) (16).
- **Range 3 to 4:** Taco Fiesta (3.50), Le Petit Bistro (3.00, inclusive) (18).
- **Invalid value 4.444:** the field shows "Use up to 2 decimals." and the list keeps the last valid range (19).
  A maximum below the minimum shows "Can't be below the minimum." (also checked during piece 3).

### 8. With a rating filter on, restaurants with no reviews are hidden — ✅ Pass

**Expected:** unrated restaurants disappear as soon as any rating limit is set, even one they'd otherwise "fit".

**Observed:** with **Max 3** only, the list shows Le Petit Bistro (3.00), Fusion Kitchen (2.00) and Golden Dragon (1.00);

![](screenshots/17-rating-max-hides-unrated.png)

### 9. Highest-rated-first is the initial default; either direction can be selected — ✅ Pass

**Expected:** the list starts sorted by average rating, highest first; switching to lowest first reverses the rated
restaurants. Per Q14, unrated restaurants come last either way, and equal ratings are ordered by name.

**Observed:**
- **Default**, labelled "Highest rated first": 4.67, 4.20, 3.50, 3.00, 2.00, 1.00, then Athens Grill, La Pino's Italia,
  Pizza Uno (unrated, by name) (10).
- **Lowest rated first:** 1.00, 2.00, 3.00, 3.50, 4.20, 4.67, then the same three unrated restaurants (21).

![](screenshots/21-sort-lowest-first.png)

- On her own restaurant's page there's no "Write a review" button (43).

**Not covered here:** viewing restaurants or posting reviews through requests sent directly to the API.

## Access, states and navigation

### 16. Unauthenticated users cannot view or change restaurants or reviews, even via direct API calls — ◐ Partly covered

**Expected:** signed-out users can't see or change restaurants or reviews.

**Observed in the app:** opening a restaurant's URL while signed out shows the sign-in page instead (70); after signing
in, the app went on to that restaurant. No restaurant or review page can be reached without signing in.

**Not covered here:** requests sent directly to the API without signing in.

![](screenshots/70-signed-out-redirected-to-sign-in.png)

### 17. Empty lists, failed requests, and missing restaurants are handled gracefully — ✅ Pass

**Expected:** no blank or broken screens: empty results explain themselves, failures explain what happened and offer a
retry, and missing items say so.

**Observed:**

| Situation | What the app shows |
|---|---|
| Owner with no restaurants (05) | "No restaurants yet · Add your first restaurant so reviewers can find it." with an Add restaurant button |
| Restaurant filters with no matches (71) | "No restaurants match these filters" with a hint and a Clear filters button |
| Restaurant without reviews (72) | "No reviews yet. Be the first to write one." |
| Review filters with no matches | "Showing 0 of 5 reviews · No reviews match these filters." with Clear filters |
| Unknown or deleted restaurant ID (73) | "Restaurant not found · It may have been deleted, or the link may be wrong." with a link home |
| Malformed restaurant ID, `/restaurants/not-an-id` | The same "Restaurant not found" |
| Unknown page, `/no/such/page` (74) | "Page not found" with a link home |
| Server unreachable while filtering (75) | "Couldn't load the restaurants. Couldn't reach the server. Check your connection and try again." with Retry; Retry recovered once the server was back (76) |
| Server error loading reviews (77) | "Couldn't load the reviews." with Retry; the rest of the restaurant page stays usable |
| Server unreachable while saving a restaurant (78) | "Couldn't reach the server…"; the form keeps everything typed, nothing is lost |
| API actually stopped when opening the app (79) | "Couldn't load the app: Request failed with status 502." with Retry. Handled, though the wording is technical |

| Unreachable while filtering | Server error on reviews |

### 18. Web navigation meets the SPA/hydration requirement — ✅ Pass

**Expected:** the client is a single-page application: moving around the app swaps content in the page without loading a
new page from the server.

**Observed:** the app is a React single-page app (Vite build, React Router). In one browser session the test went
list → restaurant → home → keyword filter → restaurant → Back → sign out → register page → sign in page (9 navigations,
including the browser's Back button). Recorded during that run:

| Measure | Value |
|---|---|
| Full page loads (document requests) during the 9 navigations | **0** |
| Page-load entries in the browser's navigation timing | **1** (the initial load only) |
| A marker set on the page before navigating was still there afterwards | **Yes**, so it was the same page throughout |

No screenshot, since nothing visible distinguishes this; the values above come from the test run.

## Reviews

### 19. Only reviewers can create reviews; ratings are integers 1 to 5, text optional — ✅ Pass

**Expected:** owners can't post reviews; ratings must be whole numbers from 1 to 5; reviews without text are allowed.

**Observed:**
- Posting without choosing stars shows "Choose a rating." and nothing is posted (36).
- The star control only offers whole ratings from 1 to 5. The text field is labelled "Your review (optional)", and a
  review without text is listed with just its stars (30).
- Owners have no "Write a review" button (43).

![](screenshots/36-review-rating-required.png)

### 20. A reviewer can post more than one review for the same restaurant — ✅ Pass

**Expected:** a second review by the same reviewer is added, not rejected or merged (Q3).

**Observed:** Rita posted two more reviews on Golden Dragon; all three of her reviews are listed, each marked "Rita (you)",
and the rating went from 1.00 (1 review) to 3.33 (3 reviews) (37).

![](screenshots/37-two-reviews-by-same-reviewer.png)

different owner or author.

**Not covered here:** sending someone else's ID as owner or author in a request made directly to the API.
